## Вариант 11: коллекция растений

Предметная область — коллекция растений, `amount` — количество растений
в экземплярах. Составлено шесть содержательных записей, категории три:
`комнатные`, `суккуленты`, `уличные`; повторяются все три.

| Название | Категория | Количество |
|---|---|---|
| Монстера | комнатные | 3 |
| Кактус опунция | суккуленты | 5 |
| Тюльпан | уличные | 12 |
| Фикус | комнатные | 2 |
| Алоэ | суккуленты | 4 |
| Роза кустовая | уличные | 6 |

Ручной расчёт сводки до запуска: `комнатные = 3 + 2 = 5`,
`суккуленты = 5 + 4 = 9`, `уличные = 12 + 6 = 18`. В алфавитном порядке
вывода: `комнатные: 5`, `суккуленты: 9`, `уличные: 18`. Поиск `суккуленты`
даёт `["Кактус опунция", "Алоэ"]` — в исходном порядке записей, не по
алфавиту. Дополнительная сортировка по убыванию суммы:
`[("уличные", 18), ("суккуленты", 9), ("комнатные", 5)]`.

## Объяснения

**Почему запись удобно представить словарём.** Запись учебного занятия
имеет разнородные поля: строковое название и целое число часов. Словарь
`{"title": ..., "hours": ...}` хранит их под понятными именами, поэтому
`record["hours"]` читается по смыслу, а не по позиции. Список пришлось бы
читать как `record[1]` — при добавлении поля `completed` индекс часов
сместился бы и все обращения поломались бы. Кортеж тоже не годится: он
неизменяемый, а задание требует изменить `hours` и добавить `completed`.
Ключей словаря может быть сколько угодно, порядок хранения не важен,
поиск по ключу — за O(1).

**Поведение `.get()`.** Запись `counts[word]` требует, чтобы ключ уже
существовал, иначе будет `KeyError`. Метод `counts.get(word, 0)` возвращает
само значение либо указанный запасной результат `0`, если ключа ещё нет.
Поэтому в `word_counts` и `totals_by_category` первый случай не отличается
от последующих: счётчик начинается с нуля и увеличивается на единицу, а
сумматор — на `amount`. Обращение `counts[word]` оставлено там, где ключ
гарантирован: в цикле печати по уже собранному словарю и в `make_pair`,
где `title` и `hours` созданы заранее.

**Почему множество сортируется перед выводом.** У множества нет индексов
и гарантированного порядка: `{"Python", "sql"}` может вывестись в любом
порядке, и результат сравнения «на глаз» станет недетерминированным.
`sorted(set(first) & set(second))` превращает результат в список с
детерминированным порядком — по возрастанию кодов символов, то есть по
алфавиту для однотипных строк. Тесты поэтому сравнивают со списком
`["git", "python", "sql"]`, а не с самим множеством.

**Словарь против списка для сводки.** `totals_by_category` возвращает
словарь «категория -> сумма», потому что категории — уникальные имена,
а суммы к ним привязаны: `totals["суккуленты"]` читается сразу. Список
пар потребовал бы поиска нужной пары перебором. Для печати в алфавитном
порядке ключи всё равно превращаются в отсортированный список —
`sorted(totals)`.

**Сортировка пар по ключу.** В `sorted_totals` аргумент `key` — лямбда
`lambda item: (-item[1], item[0])`. Кортеж ключей сравниется поэлементно:
сначала по сумме, но со знаком минус, чтобы большие суммы шли первыми
(встроенный `sorted()` сортирует по возрастанию), а при равных суммах —
по названию категории по возрастанию. Сортируется именно список пар из
`totals.items()`, сам словарь не меняется. Проверка на равных суммах —
`[("белые", 1), ("зелёные", 1)]`.

**Входные записи не изменяются.** Функции варианта только читают поля
`record["category"]` и `record["amount"]`, а результат складывают в
новые словарь и списки. Псевдонимов исходных объектов не создаётся,
поэтому после вызовов записи равны копии `[record.copy() for record in records]`
— это подтверждено отдельной проверкой `test_variant_records_unchanged`.

**Пустой текст и пустой список.** `word_counts("")` возвращает `{}`:
цикл по `"".split()` не выполняется ни разу, словарь остаётся пустым.
`totals_by_category([])` по той же причине возвращает `{}`, а
`titles_in_category([], ...)` — `[]`: цикл по пустому списку ничего не
добавляет, ветвления для особого случая не нужны.
