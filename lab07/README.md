Ручной расчёт контрольного списка `[-5, 0, 2, 5]` с порогом `2` до запуска:

| Число | Модуль | `== 2` | Подходит |
|---|---|---|---|
| `-5` | 5 | нет | нет |
| `0` | 0 | нет | нет |
| `2` | 2 | да | да |
| `5` | 5 | нет | нет |

Итог: `[2]`, порядок исходный. Пустая выборка — например
`[1, 3, 7, -7]` с порогом `2`: ни один модуль не равен `2`, результат `[]`.
Пример с повторами — `[2, -2, 2, 5, -2]` с порогом `2` даёт
`[2, -2, 2, -2]`: подходящие значения не удаляются.

## Вариант 11: модуль равен порогу

Условие отбора: `abs(number) == threshold`, то есть в новый список
попадают ровно `threshold` и `−threshold`. Граница включается, поэтому
при пороге `2` проходят `-2` и `2`, а `-3` и `3` — нет; при пороге `0`
совпадает только само число `0`. Список обходится циклом `for`,
подходящие числа добавляются через `append()` в новый список, поэтому
исходный список не меняется, а порядок и повторы сохраняются.

## Объяснения

**Возврат и вывод — разное.** `return` кладёт результат в переменную,
с ним можно дальше работать, передавать в другую функцию, сравнивать.
`print()` только показывает значение человеку и возвращает `None`.
В `functions.py` нет ни одного `print()`: функция `average([])` вернёт
`None`, и уже `main.py` решает, что показать — `Нет данных`. Если
заменить `return` на `print()` в `average`, выражение
`mean = average(numbers)` станет `mean = None`, и следующая строка
с делением упадёт: функция перестанет возвращать результат.

**Локальная переменная и параметр — разное.** Параметр — это имя в
определении функции (`number` в `sum_digits`), по которому внутрь
приходит значение аргумента. Локальная переменная — `rest` и `total`
внутри `sum_digits`: они создаются при вызове, живут до выхода из
функции и недоступны снаружи. Аргумент `507` и локальная копия `rest`
— независимые объекты: функция меняет `rest` циклом, но аргумент
вне функции остаётся `507`. Другая функция не видит `total`, пока её
не вызовут — поэтому одно и то же имя `total` в `sum_digits` и
`average` не мешает друг другу.

**Точка входа.** `main()` вызывается под `if __name__ == "__main__":`:
при прямом запуске `python main.py` блок выполняется, а при импорте
`from functions import ...` (как в тестах) — нет, поэтому импорт
тестов не запрашивает ввод и не печатает ничего лишнего.

**Проверки через `assert`.** `assert условие` при истинном условии
ничего не делает, при ложном бросает `AssertionError` и останавливает
программу с указанием строки. Тесты сравнивают ожидаемый результат с
фактическим: `select_numbers(source, 2) == [2]`, а неизменность
исходного списка проверяется сравнением `source == saved` с заранее
сделанной копией. Пустой список проверяется как `average([]) is None`,
а не `== None`, потому что `None` сравнивают через `is`.

**Демонстрация теста, находящего ошибку.** В `select_numbers` была
намеренно заменена строка `if abs(number) == threshold:` на
`if number == threshold:`. Запуск `python test_functions.py` дал
`AssertionError` на строке `assert select_numbers([-2, 2, -3, 3, 1], 2) == [-2, 2]`:
функция перестала пропускать отрицательное число с нужным модулем.
Ошибка исправлена, тесты снова проходят (код выхода `0`). Тест ловит
не конкретную строку кода, а неверное поведение, поэтому одинаково
реагирует на любую поломку условия.

**Дополнительно: `is_palindrome(text)`.** Текст сначала нормализуется
теми же правилами работы №5 (`normalize_text`: нижний регистр, края без
пробелов, один пробел между словами), затем пробелы внутри убираются и
строка сравнивается со своей обратной версией. Если нормализованный
текст пуст, функция сразу возвращает `False` — пустая строка технически
сравнялась бы с собой и дала ложноположительный результат. Проверки
написаны до реализации: `is_palindrome("А роза упала на лапу Азора")`
→ `True`, `is_palindrome("    ")` → `False`.
