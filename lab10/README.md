## Формат входного файла

`matrix.txt` — текстовый файл в UTF-8:

```text
2 3
1 -2 3
4 0 -6
```

- Первая строка: два **положительных** целых числа — количество строк и столбцов.
- Далее ровно указанное количество строк, в каждой ровно указанное количество целых чисел (разделитель — пробелы).
- Лишние и пустые строки — ошибка. Один обычный перевод строки после последней строки данных допустим.
- При любом нарушении формата `read_matrix()` вызывает `ValueError` с пояснением и номером строки. Отсутствующий файл вызывает `FileNotFoundError`.
- Входной файл открывается **только** в режиме `r`.

## Отчёт

`report.txt` записывается в UTF-8 только после того, как вход прочитан и полностью проверен:

```text
Суммы строк: 2 -2
Суммы столбцов: 5 -2 -3
Результат варианта: -3
```

Проверка чисел: строки `1 + (-2) + 3 = 2`, `4 + 0 + (-6) = -2`; столбцы `1 + 4 = 5`, `-2 + 0 = -2`, `3 + (-6) = -3`.

## Индивидуальный вариант 11

`selected_sum(matrix)` возвращает сумму элементов **последнего столбца** (индексы с нуля).
Для матрицы `[[1, -2, 3], [4, 0, -6]]` последний столбец — `3` и `-6`, сумма `-3`.
Для пустой матрицы результат `0`; для `1×1` единственный элемент учитывается один раз.
Функция работает с любой прямоугольной матрицей.

### Ручная проверка сохранности отчёта

1. В папке `lab10` выполните `python main.py` — создаётся корректный `report.txt`.
2. Временно замените содержимое `matrix.txt` на две строки (нечисловая ячейка):

   ```text
   1 2
   1 x
   ```

3. Снова запустите `python main.py`. Программа печатает:
   `Ошибка формата файла ...: Строка 2: нечисловая ячейка 'x'. Отчёт не изменён.`
4. Откройте `report.txt` — содержимое прежнее: три строки с `-3` в конце.
5. Верните `matrix.txt` исходное содержимое.

**Результат:** отчёт остался без изменений. Причина — `report.txt` открывается для записи только после успешного `read_matrix()` и расчёта; при ошибке функция `process()` возвращает `False` до строки записи.

## Вопросы к защите

**Чем отличаются ошибки формата от ошибок доступа.**
Ошибка формата (`ValueError`) означает, что файл найден и прочитан, но его содержимое не соответствует условию: пустой файл, неверный заголовок, нечисловая ячейка, неправильное число строк или столбцов, лишняя/пустая строка. Такую ошибку обнаруживает наша проверка, и в сообщении указан номер строки. Ошибка доступа (`FileNotFoundError`, другие `OSError`) означает, что файл нельзя получить: его нет, нет прав, он занят или это каталог. Их вызывает операционная система при открытии. `UnicodeError` (наследник `ValueError`) означает, что байты файла не представляют собой корректный UTF-8 — это тоже ошибка чтения, но не ошибка нашего формата. В `main.py` обработчики идут в порядке `FileNotFoundError` → `UnicodeError` → `ValueError` → `OSError`: так как `UnicodeError` является наследником `ValueError`, его нужно ловить раньше.

**Почему отчёт открывается для записи только после проверки входа.**
Если открыть `report.txt` в режиме `w` заранее, запись сразу стёрла бы прежнее содержимое, а затем при неверных данных программа прервалась бы — и старый отчёт был бы потерян зря. Поэтому сначала чтение и полная проверка, затем расчёт сумм и формирование текста отчёта **в памяти** (`build_report`), и только после этого `write_text()`. Входной файл никогда не открывается в режиме записи: он является источником данных, а не результатом.

**Дополнительное задание (CSV).** Экспорт выполняется стандартным модулем `csv`: `csv.writer` с открытием файла через `open(..., newline="")`. Значения разделяются запятыми модулем, а не вручную через `split(",")`, поэтому кавычки и разделители внутри полей обрабатываются корректно.
