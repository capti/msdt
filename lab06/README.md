## Вариант 11: числа с модулем не больше 3

Правило отбора: из `line.split()` собирается список целых чисел, в новый
список `selected` попадает число, у которого `abs(number) <= 3`. Порядок
исходный, повторы сохраняются, встроенные `len()`, `sum()` и `sorted()`
используются.

Ручной расчёт контрольного ввода `-8 -3 0 6 6 1` до запуска:

| Число из ввода | Модуль | `<= 3` | Подходит |
|---|---|---|---|
| `-8` | 8 | нет | нет |
| `-3` | 3 | да | да |
| `0` | 0 | да | да |
| `6` | 6 | нет | нет |
| `6` | 6 | нет | нет |
| `1` | 1 | да | да |

Итог: `[-3, 0, 1]`, количество `3`, сумма `-3 + 0 + 1 = -2`,
сортированная копия `[-3, 0, 1]`. Граница включительная: `-3` и `3`
проходят, `-4` и `4` — нет.

Непустой результат дополнительно проверен на наборе `-3 -3 3`
(результат `[-3, -3, 3]`, количество `3`, сумма `-3`) — видно, что
повторы не удаляются. Пустой ввод и ввод без совпадений (`8 12 -7 4`,
`-9 -7 4`) дают `[]`, `0`, `0`, `[]`.

## Объяснения

**`append()` добавляет, присваивание по индексу заменяет.**
`items.append(value)` ставит элемент в конец и увеличивает длину на один,
поэтому в `positions.py`, `variant.py` и `dedupe.py` так и нарастает
результат. Запись `items[i] = value` требует, чтобы индекс уже существовал,
иначе будет `IndexError`; длина не меняется — заменяется только значение
на своём месте. Именно поэтому в задании 2 новый список строится через
`append()`: заменить элементы по индексу на месте значило бы изменить
исходный список.

**`sorted()` возвращает новый список, `sort()` меняет исходный.**
`sorted(items)` создаёт отсортированную копию и ничего не трогает,
`items.sort()` сортирует сам список и возвращает `None` (частая ошибка —
записать `items = items.sort()`, после чего переменная станет `None`).
В `variant.py` нужна и исходная последовательность, и отсортированная
копия, поэтому используется `sorted(selected)`; если писать
`selected.sort()`, выводился бы один и тот же отсортированный список дважды.

**Исходный список сохраняется.** В `transform.py` проверка выполнена
отдельным третьим выводом: на вводе `-2 0 5 -2` после построения нового
списка исходный остаётся `[-2, 0, 5, -2]`. Это работает потому, что
цикл создаёт новый объект через `append()`, а `-number` вычисляет новое
число: списка по имени `numbers` программа нигде не меняет.

**Псевдоним и копия — разное.** Запись `copied = numbers` связала бы два
имени с одним списком, и изменение `copied` изменило бы `numbers`.
`numbers.copy()` и `sorted(numbers)` дают самостоятельные списки, поэтому
в варианте `sorted()` безопасен: он и не мог повлиять на `selected`,
но тот же принцип применяется к любым копиям.

**Пустой ввод обрабатывается до вычислений.** В `statistics.py` ветвь
`len(numbers) == 0` стоит раньше `min()`, `max()` и деления: на пустом
списке `min()` и `max()` бросают `ValueError`, а деление дало бы
`ZeroDivisionError`. Вместо этого выводится ровно одно сообщение
`Нет данных`. По той же причине `positions.py` проверяет пустой список
до `max()` и обхода.

**Почему обход позиций идёт после вычисления максимума.** Сначала
`maximum = max(numbers)` вычисляется один раз, затем `enumerate()`
даёт пары «индекс, значение» и в `positions.append(index)` попадают
все совпавшие индексы — автоматически в порядке возрастания, потому что
`enumerate()` перебирает список слева направо. Считать максимум внутри
цикла пришлось бы в двух проходах или с повторным `max()` на каждой
итерации.

**Дополнительно: удаление повторов без `set`.** В `dedupe.py` перед
`append()` проверяется `number not in unique` — по уже собранному
результату, то есть по первым появлениям. Первый экземпляр добавляется,
последующие отбрасываются, поэтому `[3, 1, 3, 2, 1]` даёт `[3, 1, 2]`,
а порядок первого появления сохраняется. `set` не использован: он вообще
не гарантирует порядок, а проверка вхождения в списке даёт нужное
поведение ценой линейного поиска — для учебного объёма данных этого
достаточно.
