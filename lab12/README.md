## Назначение

Консольная программа для учёта плана посадки растений. `amount` — количество растений, `completed` — посадка выполнена. Программа работает локально, не требует интернета и внешних библиотек. Все пути relative к папке скрипта (`Path(__file__).resolve().parent`), поэтому проект запускается после переноса в другую папку без правки путей.

## Структура

| Файл | Ответственность |
| --- | --- |
| `logic.py` | Проверка записей, добавление, поиск, статус, удаление, статистика. Изменяют список только `add_record`, `set_completed`, `delete_record` |
| `storage.py` | Чтение и запись JSON в UTF-8, без консольных диалогов |
| `main.py` | Меню, повторный ввод, сообщения, вызовы функций |
| `test_logic.py`, `test_storage.py` | Автоматические проверки через `assert` и `TemporaryDirectory()` |
| `data.json` | Небольшой вымышленный набор данных |
| `gui.py` | Доп. задание: окно поиска на основе `find_records()` |

Контракты зафиксированы в строках документации функций. `set_completed()` и `delete_record()` возвращают `True` при успехе и `False`, если запись не найдена; `find_records()` и `statistics()` исходные данные не меняют. Изменяемых глобальных переменных для состояния нет — список передаётся аргументами.

## Формат данных

`data.json` — список записей, каждая запись — словарь:

```json
[
  {"id": 1, "title": "Томаты", "category": "овощи", "amount": 4, "completed": false},
  {"id": 2, "title": "Базилик", "category": "зелень", "amount": 2, "completed": true},
  {"id": 3, "title": "Петуния", "category": "цветы", "amount": 6, "completed": true},
  {"id": 4, "title": "Огурцы", "category": "овощи", "amount": 3, "completed": false}
]
```

Правила: `id` — положительное уникальное целое; `title` и `category` — непустые после `strip()` строки (при добавлении краевые пробелы убираются); `amount` — целое не меньше нуля (логические значения не принимаются); `completed` — строго `bool`. Все пять ключей обязательны, дополнительные ключи сохраняются без обработки. Новая запись получает `max(id) + 1` (для пустого списка — `1`); после удаления существующие ID не перенумеровываются.

**Ожидаемая статистика для примера (посчитана вручную):** всего записей `4`, выполнено `2`, не выполнено `2`, всего растений `4+2+6+3 = 15`; по категориям: `зелень: 2`, `овощи: 4+3 = 7`, `цветы: 6` (в алфавитном порядке).

## Меню

1. Показать записи (по возрастанию ID; для пустого списка — `Нет записей`).
2. Добавить запись (название, категория, количество; повтор при некорректном вводе; статус `False`).
3. Найти записи (непустая подстрока названия без учёта регистра).
4. Изменить статус (явный выбор «выполнено / не выполнено»; неизвестный ID ничего не меняет).
5. Удалить запись (только после ответа `да`).
6. Показать статистику.
7. Сохранить данные (сообщение об успехе — только после записи).
8. Выйти (предложение сохранить; при ошибке записи — остаться в меню; `нет` — выйти без записи).

Неизвестная команда вызывает сообщение и повторный показ меню.

## Путь записи: от ввода до JSON и обратно

1. В меню выбрать «2 — Добавить запись». `read_text()` запрашивает название и категорию и убирает краевые пробелы, `read_amount()` повторяет ввод до целого числа ≥ 0.
2. `add_record()` присваивает `id = max(id)+1`, создаёт запись с `completed=False` и добавляет её в список.
3. Команда «7 — Сохранить данные» вызывает `save_records()`: `validate_records()` проверяет структуру, затем `json.dump(..., ensure_ascii=False, indent=2)` пишет UTF-8-файл.
4. При следующем запуске `load_records()` читает файл через `json.load()`, `validate_records()` проверяет его, и `main.py` продолжает работу с восстановленным списком. При повреждённом файле запуск прекращается без записи.
