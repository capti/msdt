## Как запустить

Проверено на Python 3.14.0, OC: Windows 10 Pro, терминал: PowerShell, IDE: Visual Studio Code.

```powershell
cd lab03
python minimum.py
python calculator.py
python point.py
python variant.py
python leap_year.py
```

Если команда `python` не найдена, используйте `py` вместо `python`.
Дробные числа и координаты вводятся с точкой: `5.1`, `2.5`.
Операция в `calculator.py` вводится одним символом: `+`, `-`, `*` или `/`.

## Вариант 11: заполненность парковки

| Диапазон | Ответ |
|---|---|
| меньше 0 или больше 100 | `Ошибка диапазона` |
| 0–59 | `Много мест` |
| 60–89 | `Мало мест` |
| 90–100 | `Почти занята` |

Границы проверены отдельно: `59` и `60` дают разные ответы, `89` и `90` тоже.
Именно поэтому в цепочке стоят `<= 59` и `<= 89`, а последняя ветвь `else`
охватывает `90–100` и не требует отдельной проверки верхней границы.

## Объяснения

**Почему `and`, а не `or`, в `point.py`.** Точка внутри прямоугольника только
тогда, когда **оба** условия выполнены одновременно: `0 <= x <= 5` и
`0 <= y <= 3`. С `or` подошла бы точка `(2, 10)`: `x` в норме, а `y` — нет.

**Почему `or` в проверке диапазона и в високосном годе.** В `variant.py`
ошибка наступает, если значение **хотя бы с одной** стороны вышло за пределы:
`occupancy < 0 or occupancy > 100`. В `leap_year.py` год високосный, если
выполняется **любое** из двух: делится на 400 или (делится на 4 и не делится
на 100). Внутри второго условия стоит `and`, потому что нужны оба признака
сразу: `year % 4 == 0 and year % 100 != 0`.

**Порядок ветвей.** В цепочке `if`/`elif`/`else` выполняется только первая
подходящая ветвь. В `variant.py` проверка диапазона стоит первой, иначе
значение `-1` попало бы в `occupancy <= 59` и получило ответ `Много мест`. В
`minimum.py` первая ветвь сравнивает первое число с обоими остальными, вторая
срабатывает, только если первое минимальным не было, а `else` оставляет
третье число. Если заменить `elif` на отдельные `if`, для набора `2, 10, 3`
будут выполнены два блока и переменная `minimum` перезапишется.

**Поведение при равенстве.** В `minimum.py` стоят нестрогие сравнения `<=`,
поэтому набор `5, 5, 5` даёт `5`: первая же ветвь подходит для равных чисел.
В `point.py` нестрогие `<=` включают границу, поэтому `(5, 3)` и `(0, 0)`
считаются подходящими. В `calculator.py` проверка `second == 0` ловит и `0`,
и `-0.0`, а стоит она внутри ветви деления, чтобы не выполнять запрещённую
операцию: иначе программа завершилась бы с `ZeroDivisionError`.
